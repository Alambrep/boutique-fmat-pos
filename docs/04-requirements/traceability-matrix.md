# Traceability matrix

> **Task:** T-08 · **Rubric criteria:** 3, 4 · **Status:** delivery 1
>
> Shows, for every client requirement (`CR`), project requirement (`PRJ`) and hypothesis (`H`), which proto-personas (`P`), scenarios (`S`), functional requirements (`FR`) and non-functional requirements (`NFR`) depend on it. It was generated from the origin columns of each artifact, so it reflects exactly what those documents cite.
>
> Use it in both directions: forward coverage (§2: is every client requirement covered?) and backward impact (§3 and §4: if a hypothesis is refuted or a question answered, what must be revised?).
>
> Regenerate with `python3 tools/trace.py` (from the repository root); the script reads the origin columns of every artifact, so the matrix cannot drift from them. `python3 tools/trace.py --check` reports whether the generated sections are up to date.

## 3. Impact if a hypothesis is refuted

- **Hypotheses with the widest impact on requirements:** H-01 (11 requirements), H-12 (6), H-02 and H-05 (4 each). H-01, H-02 and H-12 are first in the validation order (see [hypotheses §4](../02-research/hypotheses.md#4-prioritization-assumption-map)).
- **Hypotheses about the client's structure** (H-15, H-17): few links, but refuting them changes permissions and stock rules (FR-01, FR-09, FR-13, FR-22, FR-31); they are answered by the client (Q-11, Q-13).
- **Hypotheses that only shape the user model** (H-09, H-13, H-14): refuting them changes proto-personas and scenarios, not requirements.
- **Requirements that rest only on hypotheses** (no CR or PRJ in their origin): FR-03, FR-18, FR-21, NFR-04, NFR-05, NFR-09, NFR-10, NFR-11.
- **Requirements whose content depends on a hypothesis**, marked **(H)**: FR-03, FR-18, FR-19, FR-21, FR-31, FR-32, FR-37, FR-38 and the NFRs above. They are the first candidates to change.
